# 01 — Encoded PowerShell Command Execution

## Hypothesis

An actor executes PowerShell with a base64-encoded command block to hide the payload from casual review, command-line logging inspection, and simple string-matching controls.

## ATT&CK mapping

| Tactic | Technique | ID |
| --- | --- | --- |
| Execution | Command and Scripting Interpreter: PowerShell | T1059.001 |
| Defense Evasion | Obfuscated Files or Information | T1027 |

## Required telemetry

| Source | Event ID | Notes |
| --- | --- | --- |
| Sysmon | 1 (Process Create) | Provides `CommandLine`, `ParentImage`, `Hashes`, `User` |
| Windows PowerShell | 4104 (Script Block Logging) | Optional but decodes the block for you |

Sysmon config sections required: `ProcessCreate` include rules must not exclude `powershell.exe`. The stock SwiftOnSecurity config excludes some signed-parent PowerShell invocations for noise reasons, which will silently blind this rule. Verify before trusting it.

Windows audit policy required: none for Sysmon EID 1. For 4104, enable Script Block Logging via `Administrative Templates > Windows Components > Windows PowerShell > Turn on PowerShell Script Block Logging`.

**Pre-check query.** If this returns zero, the sensor is misconfigured. Fix that before touching the rule.

```spl
index=* sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
| search process_name="powershell.exe" OR process_name="pwsh.exe"
| stats count by process_name, parent_process_name
```

## Logic

Sigma rule: [`sigma/windows/process_creation/encoded_powershell_command.yml`](../sigma/windows/process_creation/encoded_powershell_command.yml)

SPL as run in this lab:

```spl
index=endpoint sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
  (process_name="powershell.exe" OR process_name="pwsh.exe")
  (CommandLine="* -enc *" OR CommandLine="* -EncodedCommand *" OR CommandLine="* -ec *"
   OR CommandLine="* -e *")
| eval encoded_len=len(CommandLine)
| table _time, user, host, parent_process_name, process_name, CommandLine, encoded_len
| sort - _time
```

Note the `-e` variant. PowerShell accepts any unambiguous prefix of `-EncodedCommand`, so `-e`, `-ec`, `-enc`, and `-encod` all work. Rules that only match `-EncodedCommand` are trivially evaded and a large fraction of published home-lab rules make exactly this mistake.

## Validation

Behavior generated by: manual baseline command. Atomic Red Team T1059.001 has not been run yet.

```powershell
powershell.exe -enc dwBoAG8AYQBtAGkA
```

The payload is base64 of the UTF-16LE string `whoami`.

Validated 2026-10-14 on host DESKTOP-TSIOB4T, user `analyst`, Sysmon 15.22 with the SwiftOnSecurity config, Splunk Enterprise 10.4.3.

Query run:

```spl
index=endpoint EventCode=1 (CommandLine="* -enc *" OR CommandLine="* -EncodedCommand *" OR CommandLine="* -ec *")
| table _time, User, process_name, CommandLine
```

This is not identical to the SPL in the Logic section. It has no `sourcetype` or `process_name` filter and no `-e` clause. The Logic SPL filters on `sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"`, but in this lab the Sysmon events arrive with sourcetype `XmlWinEventLog`, so the Logic SPL needs to be re-run as written before it is relied on.

Result: Detection returned exactly 1 event. `CommandLine` was captured in full, including the encoded payload: `"C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe" -enc dwBoAG8AYQBtAGkA`. Attributed to `DESKTOP-TSIOB4T\analyst`.

This confirms the rule fires on the baseline invocation. It does not test the `-e` prefix variant, Atomic Red Team T1059.001, or invocations that fall inside the SwiftOnSecurity PowerShell exclusions.

## False positives

**Anticipated false positives.** The sources below are expected in an enterprise environment. None were observed in this lab.

| Source | Frequency | Handling |
| --- | --- | --- |
| Software installers and MSI custom actions | Occasional | Filter on trusted `ParentImage` plus signature status, not on parent name alone |
| Endpoint management agents (SCCM, Intune, RMM tools) | Routine | Allowlist by parent image hash, review quarterly |
| Developer tooling and CI agents | Environment dependent | Scope by host group rather than suppressing globally |

The lab VM has no endpoint management agents, no developer tooling, and no real user activity. Its benign baseline is not representative of a production endpoint, and no false positive rate has been measured.

Suppressing by parent process name alone is unsafe: parent name is trivially spoofable and an actor who learns the allowlist inherits it.

## Severity and response

**Severity:** Medium. Encoded PowerShell is common enough in legitimate tooling that this should not page anyone on its own, but it should always be reviewed.

**Triage steps:**
1. Decode the block. `[System.Text.Encoding]::Unicode.GetString([Convert]::FromBase64String($b64))`
2. Pivot on `ProcessGuid` to build the full process tree. What launched it and what did it launch.
3. Check Sysmon EID 3 for outbound connections from the same `ProcessGuid` within 60 seconds. Encoded command plus immediate egress is the escalation trigger.
